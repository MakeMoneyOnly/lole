# Hermes Insights Loop

The self-improvement engine for the Lole COL. Once per week (or on demand),
the COL Orchestrator runs an Insights Scan across all agent sessions from the
past N days, surfaces patterns and regressions, and proposes improvements.

---

## When to Run

- **Weekly Routine**: Every Monday at 08:00 EAT (CEO Routine)
- **On Demand**: When any VP reports consistent blockers or cost overruns
- **Post-Incident**: After any Sentry production incident

---

## Insights Scan Procedure

### Step 1: Collect Session Data (last 7 days default)

Query `.col/memory/sessions/` for all session files from the past N days.
Group by:

- `source` (which agent/department)
- `end_reason` (complete, blocked, compressed, error)
- Token/cost metrics

### Step 2: Compute Per-Agent Metrics

For each agent, calculate:

```
completion_rate    = sessions[end_reason='complete'] / sessions_total
block_rate         = sessions[end_reason='blocked'] / sessions_total
compression_rate   = sessions[end_reason='compression'] / sessions_total
avg_tokens         = mean(output_tokens) per session
avg_cost_usd       = mean(estimated_cost_usd) per session
escalation_rate    = count(request_board_approval) / sessions_total
```

### Step 3: Detect Patterns

Flag any agent where:

- `completion_rate < 0.7` → agent is frequently blocked, needs skill update
- `compression_rate > 0.3` → agent's tasks are too large, needs decomposition
- `avg_tokens > 8,000` → agent context is ballooning, review prompt efficiency
- `block_rate > 0.2` → systemic blocker, needs VP attention
- `escalation_rate > 0.5` → agent over-escalating, needs broader permissions

### Step 4: Surface Cross-Agent Patterns

Look for recurring themes across ALL sessions:

- Most common blocker keywords (e.g., "ERCA", "PowerSync", "type error")
- Most expensive departments by token cost
- Departments with zero sessions (silent failure — agents not running)
- Wiki drift: sessions referencing files that no longer exist

### Step 5: Generate Insights Report

Write to `.col/memory/wiki/synthesis/weekly-insights.md`:

```markdown
# COL Weekly Insights Report

**Period:** {start_date} → {end_date}
**Generated by:** COL Orchestrator (hermes-insights-loop)

## 🟢 Healthy Departments

{list departments with completion_rate >= 0.9}

## 🟡 Needs Attention

{list departments with issues + specific metric causing concern}

## 🔴 Critical

{list departments with completion_rate < 0.5 or zero activity}

## 💰 Cost Analysis

| Department | Sessions | Avg Tokens | Avg Cost | Total Cost |
| ---------- | -------- | ---------- | -------- | ---------- |

...

## 🔁 Top Recurring Blockers

1. {blocker keyword} — appeared in {N} sessions across {departments}
2. ...

## 📈 Improvement Recommendations

1. {specific, actionable recommendation with owner}
2. ...

## 🧠 Skill Gaps Detected

{any agents that triggered skills not in their assigned toolset}
```

### Step 6: Dispatch Action Items

For each item in the "Critical" or "Needs Attention" sections, create a
Paperclip issue assigned to the responsible VP with:

- `priority: high`
- `assignee: {vp-slug}`
- `description: {specific metric + recommendation}`

---

## Self-Improvement Loop (Write-a-Skill)

When the Insights Report identifies a **recurring pattern** (the same problem
appearing in 3+ sessions across 2+ weeks), the Orchestrator MUST:

1. Extract the pattern into a new `.agents/skills/` entry using `write-a-skill`
2. Register the new skill in `AGENTS.md` Skill Activation Matrix
3. Log the skill creation to `.col/memory/episodes/skill-evolution-log.md`

**Example:** If "ERCA signature validation" appears as a blocker in 5 sessions,
create a dedicated `erca-signature-validation` skill that codifies the fix.

## Integration with Obsidian

The Insights Report is written as Obsidian-compatible Markdown with:

- `[[wikilinks]]` to relevant Department nodes
- `#insights` tag for filtering in Graph View
- YAML frontmatter with `date`, `period`, `generated_by` fields
